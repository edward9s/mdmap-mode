# mdmap mode

*[English](README.md)*

> 本專案修改自 [Mindmap Mode](https://github.com/PHANTOM-Nw/obsidian-mindmap-mode)，原作者為 PHANTOM-Nw。保留原專案的 MIT 授權及版權聲明。

把任意 Obsidian 筆記切換成可編輯的放射狀心智圖 —— 就像切到閱讀模式一樣。同一個分頁、同一個檔案，**不會產生任何額外檔案**。

你在圖上做的每一次修改，都會以最小的行級編輯寫回原來的 `.md` 筆記。切回去，你的筆記還是你的筆記。

畫布的操作手感接近 XMind、MindNode 這類桌面心智圖工具，但資料自始至終就是你那份 markdown 筆記本身。

## 它做什麼

- **是一種檢視模式，不是匯出。** 切換只是把目前 leaf 的檢視模式類型換掉，同一個 `TFile` 仍然開在同一個分頁裡。不生成、不複製、不寫任何附屬檔案。
- **你的大綱就是心智圖。** 標題按層級巢狀，縮排的列表掛在它所屬的標題下面。你已經寫好的內容本身就是結構。
- **節點可以帶註解。** 在標題或列表項下面寫一行 `: text`，它就成為該節點的[註解](#節點註解)：以灰色文字貼在卡片下方，而不是單獨成卡。在 Obsidian 的編輯模式和閱讀模式裡，這仍然只是一行以冒號開頭的普通文字。
- **開啟時是折疊的。** 進入時只顯示根節點和一級分支，每個折疊按鈕上標著背後藏了多少節點。展開一個分支只會多出一層，不會把整棵子樹攤開。
- **回來時還是你離開時的樣子。** 再開啟同一篇筆記，折疊形狀原樣恢復，鏡頭也落在你上次正在看的那張卡片上。這份狀態存在外掛本身的資料裡，從不寫進筆記 —— 不產生 diff，也不會有合併衝突。
- **公式會呈現。** `$\lambda$` 和 `$$\sum_{i=1}^{n} x_i$$` 交給 Obsidian 內建的 MathJax 排版。而 `$5 and $10` 這樣的價格仍然是價格。
- **在畫布上直接編輯。** 重命名、新增、刪除、縮排、拖曳改父級、拖曳調順序、折疊、勾選核取方塊 —— 每一項都就地改寫筆記。
- **其餘內容保持不變。** frontmatter、圍欄程式碼區塊、表格、HTML 和連結永遠不會被重新格式化。你沒有編輯過的行會逐位元組原樣返回，包括 CRLF 換行。

## 切換到心智圖

對目前已經開啟的筆記，下面任意一種方式都行：

| 位置 | 方式 |
| --- | --- |
| 命令面板 | **Toggle mind map view**（建議綁個快捷鍵，用起來就跟原生一樣） |
| 筆記標題欄 | 其他檢視模式按鈕旁邊的分支圖示 |
| 左側邊欄 | 側邊欄裡的分支圖示 |
| 右鍵選單 | 右鍵筆記 → **Open as mind map** |

切回去時會回到你原來所在的 markdown 模式 —— 原始碼模式或閱讀模式。

### 搜尋節點

`Ctrl`/`Cmd`+`F` 會在畫布上方開啟搜尋條 —— Obsidian 內建的編輯器搜尋管不到心智圖，所以心智圖內建一個。預設是不區分大小寫的子串匹配，`.*` 按鈕切換正規表示式；正規表示式寫到一半編譯不過時只會把輸入框標紅，不會拋錯。命令面板裡還有一條 **Find in the mind map**，想自定義快捷鍵就綁它。

匹配的是你在卡片上看到的文字：`**bold** text` 能被"bold text"搜到，`[[note|Label]]` 只能按"Label"搜到、按"note"搜不到，公式則按 TeX 原始碼匹配。跳到折疊分支裡的命中會自動展開；再往下一個命中走時，上一處為搜尋展開的分支隨即收合，走一遍查詢不會把整張心智圖一路攤開。關閉搜尋條時其餘的也一並收合，只留下你停在的那個命中所在的那條路徑，卡片仍然選取、仍然在畫面裡 —— 搜尋期間你自己手動展開的分支則始終保留。這一版只給命中的整張卡片加高亮環，不高亮卡內的具體子串；段落、程式碼區塊、表格這些內容卡片也不參與搜尋。

跨越"標題 / 列表"邊界拖曳時，被移動的塊會自動轉換：把一個標題拖到列表項上，整棵子樹變成巢狀列表；把一個列表項拖到標題上，它變成頂級列表。核取方塊狀態在往返過程中不會丟。落到某個節點旁邊時同理 —— 它會寫成目標那樣的形態，因為一個列表項寫在標題後面就成了那個標題的內容，而不是它的同級。

不想動滑鼠就按 `Ctrl`/`Cmd`+`↑` / `↓`：選取的節點連同整棵子樹跟上面 / 下面那個同級對調，移完還是選取它。已經在頭一個或最後一個位置時什麼都不會發生，檔案也不會被寫。命令面板裡另有 **Move the selected node up / down among its siblings** 兩條命令，預設不綁快捷鍵，想自定義就綁它們。

一級分支不參與排序，拖曳和快捷鍵都一樣：它們由佈局按各自的體量動態分到根節點的左右兩側，順序歸佈局管。拖到一級卡片上仍然是改變父級，整張卡都是如此。第二級往下則按檔案裡的先後自上而下排列，拖到邊緣就能改這個順序。

### 節點註解

標題或列表項下面以 `: ` 開頭的行是註解：它貼在該節點的卡片下方，以灰色文字和左側垂直線顯示，不再單獨成卡。連續的 `: ` 行保留換行，單獨一行 `:` 表示註解裡的空行，過長的行按正文卡片的寬度折行，也就是 **Maximum card width** 的 1.6 倍。註解可以把卡片撐得比標題本身更寬，最寬到這個寬度；節點標題仍按 **Maximum card width** 折行，卡片和它下面的灰條始終一樣寬。

```markdown
### 泛化性
: 把一項能力遷移到陌生環境。
:
: 這是另一個段落。

- 在線自適應
  : 在使用過程中不斷變好。
  : 第二行說明。
```

這是本外掛的一個書寫約定，不是 Markdown 的語法。在 Obsidian 的編輯模式和閱讀模式裡，`: ` 行就是一行以冒號開頭的普通文字，筆記在別處照常閱讀 —— 不會為了心智圖改寫原文，也不會往檔案裡塞只有心智圖看得懂的東西。

列表下面的註解縮排到該列表項的內容列，也就是這一項自己的文字所在的那一列。這一列同時決定這行註解歸誰：`: ` 行會把列表的層級重新錨定到內容列與它相同的那一項，因此寫在它後面、縮排更深的列表項會成為這一項的子項，而不是上一項的子項。超出內容列四個空格是縮排程式碼；圍欄程式碼則完全不參與識別。

雙擊註解，或在節點右鍵選單裡選 **Add annotation** / **Edit annotation**，就會開啟一個多行編輯框。按 Enter 換行，空行照樣保留，冒號前綴由外掛寫回檔案。`Ctrl`/`Cmd`+`Enter` 或 **Save** 儲存；清空後儲存即刪除註解。寫回只替換註解自己的那幾行，筆記其餘部分一個位元組都不變，註解也隨所屬節點一起移動。如果編輯期間檔案裡的註解被改過，儲存會被拒絕、編輯框保持開啟，草稿還在，可以先複製出來。

節點折疊時註解仍然顯示，也不受 **Show note content** 影響。在 Appearance 裡關掉 **Inline annotations**，`: ` 行就回到原來的正文卡片。心智圖裡的搜尋匹配的是節點標題，不匹配註解。被節點來源或標題深度設定排除在心智圖之外的結構，其 `: ` 行保留為普通正文。

### 段落、程式碼區塊和表格

不是標題也不是列表項的內容，會原封不動留在筆記裡的原位置 —— 但它們會作為自己的卡片出現在心智圖上，跟所屬分支一起折疊和展開，按在檔案中的先後順序穿插在同級節點之間。程式碼區塊和表格保持等寬字型和原有換行，段落則按正常字型排版（公式一樣會呈現）。

卡片上看到的只是預覽：內容很長時會被截斷，而心智圖自己的呈現器只認行內語法。點卡片角上的 **⤢** 按鈕，就能在彈出的對話框裡看到整塊內容，並且由 Obsidian 自己呈現 —— 行間公式、表格、程式碼高亮、callout 都和閱讀模式裡一模一樣。在那個對話框裡切到 **Source**（或者直接雙擊卡片）即可編輯這一段，儲存只會改寫那幾行。

內容卡片不能被重命名、拖曳或刪除 —— 那幾行歸筆記所有，心智圖只是把它們顯示出來。

如果不想在圖上看到它們，在設定裡關掉 **Show note content** 即可。

## 匯出

四條命令可以把目前這張心智圖另存為一個檔案：**Export mind map as Canvas**、**as SVG**、**as PNG**、**as HTML**。心智圖是目前分頁時，命令面板裡就有它們，分頁的"更多選項"選單裡也有。心智圖右下角工具列的上方，還有單獨一排這四個匯出按鈕。

匯出的就是你看到的那一張：目前的折疊狀態、目前的佈局（左右分布或單側）、分支配色開著就帶上、顏色取自你正在用的主題。折疊起來的分支不會出現在檔案裡，選取框、搜尋高亮和懸停出來的按鈕也不會。

檔案就放在筆記旁邊，同名換後綴。絕不覆蓋已有檔案：名字被佔用時會依次變成 `筆記 1.svg`、`筆記 2.svg`，和 Obsidian 自己處理重名的方式一致。

- **Canvas** 是可以繼續編輯的那一種。每張卡片變成一個文本節點，裡面是原始 Markdown，所以連結、公式和格式都還是活的；內容卡片寫入的是整塊原文，而不是圖上那段預覽。連線變成 canvas 的邊，從分支生長的那一側出發。新增的 `.canvas` 會在新分頁裡開啟。
- **SVG** 是矢量圖：可以任意放大，文字仍然是文字，還能選取和搜尋。但它不是拿來改樣式的檔案 —— 心智圖當時的每一項樣式都被內聯寫進了檔案，這也正是它能獨立開啟的原因。
- **PNG** 是位圖，按心智圖自身尺寸的兩倍呈現；圖太大時會縮到畫布 16384 像素的上限之內，這種情況通知裡會說明。
- **HTML** 是一個不含腳本的靜態頁面，任何瀏覽器都能開啟。

三種圖片格式都把樣式內聯進了檔案，所以檔案可以獨立開啟 —— 代價是：需要另外去取的東西不會跟著走。筆記內容裡引用的圖片不會被畫出來，主題的網路字型也沒有嵌進去，所以文字會回退到開啟檔案的那台機器已有的字型。

## 安裝

尚未上架 Obsidian 社群外掛目錄，所以需要手動安裝：

```bash
npm install
npm run build
```

然後把 `main.js`、`manifest.json` 和 `styles.css` 複製至你的 Obsidian 筆記庫：

```bash
mkdir -p /path/to/vault/.obsidian/plugins/mdmap-mode
cp main.js manifest.json styles.css /path/to/vault/.obsidian/plugins/mdmap-mode/
```

在 *設定 → 社群外掛* 裡啟用 **mdmap mode**。

做開發的話改用符號連結，這樣 `npm run dev` 會就地重新編譯，然後用 *不儲存而重新載入應用*（或 Hot-Reload 外掛）來載入改動：

```bash
ln -s "$PWD" /path/to/vault/.obsidian/plugins/mdmap-mode
npm run dev
```

儲存庫裡的 `test-vault/` 是一個範例筆記庫 —— 把那個資料夾作為庫開啟，再把外掛符號連結進 `test-vault/.obsidian/plugins/`，就能在不碰你真實筆記的情況下試用。

## 設定項

節點來源（標題和列表 / 僅標題 / 僅列表）、最深標題層級、根節點策略、新增列表項的縮排單位、佈局（平衡式或單側）、分支配色、是否把正文內容顯示為卡片、是否把 `: ` 行顯示為註解、卡片寬度、間距、滾輪行為、是否記住折疊狀態，以及是否在標題欄添加按鈕。

Appearance 裡的 **Inline annotations** 預設開啟：標題或列表項下面的 `: text` 行會畫成該節點的[註解](#節點註解)，而不是單獨的正文卡片；關掉它，這些行就恢復成普通內容卡片 —— 開關在哪一邊，筆記本身都不會被改動。

關掉**記住折疊狀態**後，每張心智圖都會像以前一樣開啟成"根 + 一級分支"。另外還有一條命令 *Forget the saved fold state for this note*，用來只清掉某一篇筆記的狀態，不必去動設定。

最後一組是 **Shortcuts**：心智圖響應的每個按鍵各佔一行，顯示它目前綁的鍵。**Record** 會把你按下的下一個鍵記為新綁定，按什麼都算 —— 想放棄就按 `Esc`。**×** 會清空這一行，讓這個動作不綁任何鍵；只有改過的行才會出現那個重置箭頭，點一下就恢復預設。兩個動作綁到同一個鍵時，兩行都會提示，並且由列在上面的那個響應。組末尾的 **Restore all defaults** 一次清掉所有改動。只有你改過的部分會被存下來，所以以後版本調整了某個預設鍵，你這邊也會跟著變。

## 往返改寫是怎麼保證安全的

每一次操作都是對原文的一次**行區間替換**。心智圖只是一層投影：每個節點都記著自己來自哪一行，以及那一行的確切組成部分（縮排、標記符、空格、核取方塊、文字、行尾後綴），因此它能逐字元地把自己重建出來。檔案永遠不會從樹重新生成。

這個不變量是由測試套件強制保證的，而不是靠約定：

```bash
npm test
```

它驗證的內容包括：解析 / 序列化的往返在 frontmatter、CRLF、波浪號圍欄與巢狀圍欄、有序列表、空列表項、帶閉合井號的標題上都逐位元組一致；圍欄程式碼區塊永遠不產生節點；**任何操作都不會碰 frontmatter**；以及在一個內容豐富的樣例上，每一種合法的改父級操作往返之後程式碼內容依然完好。

佈局也有覆蓋 —— 在平衡式和單側兩種模式下，深而不均的樹裡都斷言卡片永不重疊；同一棵樹連續排版兩次斷言落點完全相同（MathJax 刷新樣式表之後，心智圖會重新測量而不重建 DOM）。`$…$` 的分隔符規則單獨放在一個零依賴模組裡，因此可以用同樣的方式測試。

## 已知限制

- **Setext 式標題**（用 `===` 或 `---` 底線標出的標題）被當作正文內容而非節點。它們會被原樣保留；心智圖讀取的是 ATX（`#`）式標題。
- 當筆記有且僅有一個頂級標題時，它就是根節點，否則用檔案名稱。檔案名稱根節點無法在心智圖裡重命名 —— 那等於重命名檔案。
- 折疊狀態按筆記記在外掛自己的 `data.json` 裡，絕不寫進筆記本身。節點是靠標題路徑找回來的，所以改掉某個節點的文字，它自己的折疊狀態就找不回來了，周圍的分支不受影響。只保留最近 200 篇筆記；停在預設折疊狀態的筆記什麼都不存。
- 行內公式採用了比 Obsidian 自身更嚴格的 `$…$` 規則 —— 公式內容不能以空白開頭或結尾，閉合的 `$` 後面也不能緊跟數字。這正是 `$5-$10` 能保持是價格的原因，代價是 `$x$2` 會保持原文不呈現。
- 把帶核取方塊的列表項移動到標題位置時，`[x]` 會變成純文字（標題不能帶核取方塊）。移回去時會恢復成真正的核取方塊。

## 開發

```
src/model/     解析器 + 變更引擎 —— 純函數，不 import Obsidian
src/layout/    tidy-tree 佈局
src/view/      畫布、卡片、連線、互動、公式、TextFileView
src/main.ts    外掛：檢視模式註冊、模式切換、命令
```

`src/model` 和 `src/layout` 不依賴 DOM 也不依賴 Obsidian，所以可以用 `node --test` 直接做單元測試（Node 22.6+ 原生剝離 TypeScript 類型 —— 無需構建步驟，也無需測試框架）。
